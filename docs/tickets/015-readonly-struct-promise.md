# CHOP-015: Make HandlingResultPromise a readonly struct

## Priority: 🟡 P2 — Moderate
## Type: Correctness / Safety
## Component: Native/Messages

---

## Problem Statement

`HandlingResultPromise` is declared as a mutable struct:
```csharp
public struct HandlingResultPromise  // NOT readonly!
```

While `HandlingCompletionPromise` is correctly declared:
```csharp
public readonly struct HandlingCompletionPromise  // Correct
```

Mutable structs in C# are a well-known footgun:
1. Passing by value creates copies; mutations to copies are silently lost
2. Calling methods on struct properties creates hidden copies
3. `in` parameters with mutable structs create defensive copies

Since `HandlingResultPromise` is passed by value (it's a struct), any method that looks like it modifies `this` actually modifies a copy when accessed through certain patterns.

## Solution Design

```csharp
// HandlingResultPromise.cs
public readonly struct HandlingResultPromise  // Add 'readonly'
{
    // All fields must be readonly (they already are via 'readonly' backing)
    // All methods are already declared 'readonly' where appropriate
}
```

Audit all fields — they should already be readonly since the struct stores a single `IHandlingPromiseSource _source` reference that never changes after construction.

#### Test 1: Struct Remains Unchanged After Method Call
```
GIVEN a HandlingResultPromise
WHEN OnSuccess(callback) is called
THEN the original struct's Source reference is unchanged
```

#### Test 2: Copy Semantics Are Safe
```
GIVEN promise = handler.TryHandle(message)
AND copy = promise
WHEN copy.OnSuccess(action) is called
THEN original promise is unaffected
AND action still fires (both share same source)
```

#### Test 3: In Parameter Doesn't Cause Defensive Copy
```

```
